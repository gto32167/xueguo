# Workflow Learn

## 定位

本 Skill 只维护项目空间中的轻量知识资产，不修改需求基线，不自动改变业务代码，不把候选知识直接视为事实。

## 前置条件

1. 任务已执行 finish 并有交付说明。
2. 验证报告明确区分已验证结论和未验证风险。
3. 能定位任务绑定的 requirement_version 和最终人工责任人。

## 流程

1. 读取任务卡、需求基线、验证报告、交付说明和已使用的项目记忆。
2. 复制 templates/retrospectives/task-retrospective.md 到项目空间 retrospectives/ 并完成复盘。
3. 只提炼可复用结论，按以下类型写入 memory/：
   - DOMAIN_RULE：经人工确认的业务规则。
   - SERVICE_MAP：有代码或调用证据的服务关系。
   - KNOWN_PITFALL：已复现并验证的常见遗漏。
   - VALIDATION_RECIPE：至少被一次真实任务验证的最小验证组合。
   - TOOL_CANDIDATE：近似推理或排查步骤累计出现 3 次以上。
4. 新条目默认标记为 CANDIDATE；没有人工确认不得晋级 VERIFIED。
5. 发现旧条目误导、过时或适用范围变化时，记录降级建议；不得静默覆盖历史结论。
6. 更新 status/project-status.yaml 的待决策、风险和下一步索引。

## 反推理规则

- 同类步骤少于 3 次：保留为复盘记录，不新增工具。
- 达到 3 次：登记 TOOL_CANDIDATE，说明输入、输出、验证方式和失败边界。
- 能用确定性脚本完成的工作优先固化为工具；仍需业务判断的工作保留给人。

## 门禁

- 聊天全文、完整构建日志、凭据、客户敏感数据和大段代码不得写入项目记忆。
- CANDIDATE 只能作为检索线索，Agent 使用时必须回到代码、测试、需求基线或人工决策验证。
- VERIFIED 必须记录证据索引、适用范围、确认人和确认时间。
- AI 不得成为最终责任人。

## 交付要求

说明复盘路径、新增或更新的候选记忆、建议晋级或淘汰的条目、工具候选、仍需人工处理的决策，以及未沉淀内容的原因。
