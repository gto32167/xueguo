# Change Route

## 流程

1. 读取任务、BUG 或需求描述，以及已知的代码入口和项目约定。
2. 按以下内置规则检查接口、数据、跨模块、权限/资金/状态、新依赖和不可逆操作；框架仓的完整说明见 `docs/change-risk-routing.md`。
   - 全部为否：L0（局部文案、日志、样式或机械修复）或 L1（单模块内部 BUG）。
   - 接口、数据、跨模块、消费者、状态逻辑或新依赖任一为是：至少 L2。
   - 删除、迁移、资金、权限边界、历史数据重新解释或其他不可逆操作：L3。
3. 写入轻量变更记录，或在任务/BUG 卡中填写 `change_level`、`scope_summary`、`spec_refs` 和 `verification`。
4. 说明选择该级别的证据、最小必需产出和升级条件。

## 输出要求

- 不因为“可能有影响”直接升级；指出具体影响对象或待确认问题。
- L0/L1 不生成空的 `proposal.md`、`design.md` 或 `impact.md`。
- 任何实际跨模块、契约、数据、权限、状态、新依赖或不可逆影响都必须升级到 L2/L3。
- 最终责任人必须是人，验证结果必须区分已验证结论和未验证风险。
