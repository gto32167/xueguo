# 并行开发与选择性发布

## 原则

开发可以并行，发布和共享测试环境必须受控。每个任务使用独立分支或 Worktree，发布使用明确的 Release Candidate 清单。

## 冲突检查

并行前登记仓库、模块、类、接口、数据表、迁移脚本和状态机写入范围。codebase-memory-mcp 用于调用链和影响分析，文本搜索补充 XML、YAML、POM、Topic 和反射配置。

冲突分为：

- 绿色：无共享写入，可以并行。
- 黄色：存在共享契约，需要同步基线。
- 红色：修改同一规则或接口，串行集成。
- 黑色：资金或不可逆数据变更，禁止并行实施。

## 选择性发布

发布清单必须记录各仓提交号、制品版本、数据库迁移、Feature Flag、包含任务和排除任务。清单冻结后不允许原地修改，内容变化创建新版本。

数据库采用 Expand-Migrate-Contract；跨服务接口优先增加兼容字段并保留兼容窗口。
